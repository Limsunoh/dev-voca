# 한글 발음 표기 규칙

발음기호(IPA) 옆에 한글을 나란히 둔다. **한글만 읽어도 통해야 한다** — 이것이
이 표기의 유일한 목적이다.

타겟이 영어가 약한 주니어라 IPA 는 또 하나의 배워야 할 기호다. 그 벽을 없애되,
틀린 발음을 굳히면 안 하느니만 못하다.

## 왜 "애플" 이 아니라 "애쁠" 인가

한국어식 표기(`애플`, `쓰레드`, `커밋`)는 이미 굳은 말이라 읽기는 쉽지만 원음과
멀다. 특히 셋이 문제다.

| 문제 | 예 | 결과 |
|---|---|---|
| 삽입 모음 | thread -> 쓰**레**드 | 없는 음절이 생겨 3음절이 된다 |
| 강세 소실 | deploy -> 디플로이 | 평평하게 읽어 안 통한다 |
| 없는 소리 | thread -> **쓰**레드 | s 소리가 되어 다른 단어가 된다 |

그래서 **음절 수를 원음에 맞추고, 강세를 표시하고, 한글에 없는 소리는 한글로
쓰지 않는다.**

## 규칙

### 1. 강세는 굵게

가장 중요하다. 어디에 힘을 주느냐가 통하느냐를 가장 크게 가른다.

```
deploy      /dɪˈplɔɪ/     드**플로이**
refactor    /riˈfæktər/   리**f액**털r
```

2차 강세(`ˌ`)는 표시하지 않는다. 하나만 굵게 해야 눈에 들어온다.

### 2. 끝자음은 받침으로

삽입 모음을 막는 핵심 규칙이다. `드`, `트`, `크` 를 붙이지 않는다.

```
bug         /bʌɡ/         **벅**          ("버그" 아님)
commit      /ˈkɑmɪt/      **카**믿        ("커밋" 아님)
thread      /θred/        **th렏**        ("쓰레드" 아님)
deployed    /dɪˈplɔɪd/    드**플로읻**
```

받침으로 안 되는 소리(sh, ch, j 등)만 영문으로 둔다.

```
cache       /kæʃ/         **캐**sh
patch       /pætʃ/        **패**ch
```

### 3. 한글에 없는 소리는 영문 그대로

한글로 쓰면 그 잘못된 소리가 그대로 굳는다. 예외를 두지 않는다 — 예외가 하나
생기면 어디까지가 예외인지 566개마다 판단해야 한다.

| 소리 | 표기 | 예 |
|---|---|---|
| θ, ð | `th` | thread -> **th렏** |
| f | `f` | file -> **f아일** |
| v | `v` | version -> **v어**즌 |
| ʃ | `sh` | cache -> **캐**sh |
| 끝의 r | `r` | refactor -> 리**f액**털r |
| 어두의 l | `l` | local -> **l로**우클 |

어두의 `l` 만 표기가 겹쳐 보인다(`l` 과 `로`). 다른 소리는 영문이 한글을
대체하지만 `l` 은 자음 하나라 뒤에 모음이 없으면 못 읽는다. `l` 은 "혀끝을
입천장에 붙이고 시작하라" 는 표시이고 `로` 가 그 뒤 모음이다.
| z | `z` | zone -> **z오운** |

**`-tion` 도 예외가 아니다.** 빈도가 높지만 `션` 으로 쓰면 sh 소리가 한글 `시`
로 굳는다.

```
authentication  /ɔˌθentɪˈkeɪʃn/   오th엔티**케이**sh언
migration       /maɪˈɡreɪʃn/      마이**그레이**sh언
```

읽기가 한 번 걸리는 것은 감수한다. 그 걸림이 "여긴 한글 소리가 아니다" 라는
신호이기도 하다.

감수하는 비용을 세어봤다 - 첫 566개 중 `sh언` 이 들어간 것은 **37개(6%)** 다.
예외를 둘 만큼 흔하지 않다.

### 4. 슈와(ə)는 가장 약하게

한국어에는 약한 모음이 없어 또박또박 읽게 된다. 앞뒤에 묻히도록 적는다.

```
about       /əˈbaʊt/      어**바웉**
support     /səˈpɔrt/     써**폴t**
```

### 5. 어두의 된소리

영어의 무기음 p, t, k 는 한국어의 ㅍ, ㅌ, ㅋ 보다 ㅃ, ㄸ, ㄲ 에 가깝다.
s 뒤에서 특히 그렇다.

```
schema      /ˈskimə/      **스끼**머      ("스키마" 아님)
apple       /ˈæpəl/       **애**쁠
```

### 6. 약어는 발음기호가 갈라준다

개발 용어의 3분의 1이 약어인데 두 갈래다. 어느 쪽인지는 **발음기호에 공백이
있는지**로 알 수 있다.

```
API   /ˌeɪ pi ˈaɪ/    공백 있음 = 철자로 읽는다   에이 피 **아이**
HTTP  /ˌeɪtʃ ti ti ˈpi/                          에이ch 티 티 **피**
JSON  /ˈdʒeɪsɑn/      공백 없음 = 단어로 읽는다   **제이**싼
SQL   /ˈsikwl/                                    **씨**퀄
YAML  /ˈjæml/                                     **야**믈
```

철자로 읽는 것은 글자 사이를 띄운다. 붙여 쓰면 한 단어로 읽게 된다.

## 자세히 (단어만)

간단 표기 아래에 접어둔다. 눌러야 보인다. **문장에는 넣지 않는다** — 길어서
화면이 감당하지 못하고, 문장은 단어 경계가 뭉개지는 것만 알면 된다.

세 줄을 넘기지 않는다.

```
thread      th렏
            th 는 혀끝을 윗니에 살짝 대고 바람을 낸다. "쓰" 로 읽으면
            s 소리가 되어 다른 단어가 된다.

deploy      드플로이
            앞은 거의 안 들리게, 뒤 "플로이" 에 힘. 평평하게 읽으면
            안 통한다.
```

## 문장

간단 표기만. 단어 경계가 뭉개지는 것(연음)을 그대로 적는다.

```
Could you rebase this onto main?
쿠쥬 리**베이**스 디s 온투 **메**인?
```

## 검수할 때 보는 것

1. **한글만 읽었을 때 통하는가.** 이것이 유일한 기준이다
2. 음절 수가 원음과 같은가 (삽입 모음이 없는가)
3. 강세가 IPA 의 `ˈ` 위치와 맞는가
4. 한글에 없는 소리를 한글로 쓰지 않았는가
5. 같은 패턴이 다른 단어에서 다르게 적히지 않았는가
6. **약어라면 철자·단어 판단이 맞는가.** 규칙 6은 발음기호의 공백으로
   가르는데, 개발 용어는 사전에 없어 발음기호가 비어 있는 것이 많다.
   그 자리에서는 규칙이 작동하지 않으니 사람이 직접 판단해야 한다
7. 강세 별표(`**`)의 짝이 맞는가. 짝이 안 맞으면 화면에서 엉뚱한 곳이
   굵어지는데 티가 안 난다
